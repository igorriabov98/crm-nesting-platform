# Импорт листового металла

На основном складе кнопка «Импорт из Excel» доступна пользователям с `inventory/manage`.
В окне доступны только заводы, которые пользователь может пополнять. Скачайте шаблон,
заполните лист «Импорт», выберите завод и проверьте файл. Подтверждение добавляет листы
к текущему остатку. Брони сохраняются. Примеры на листе «Инструкция» не импортируются.

Формат: `.xlsx`, до 3 МБ, до 2 000 заполненных строк; до 30 МБ после распаковки.
Нулевые количества пропускаются. Формулы, ошибки Excel, дробные количества и
объединённые ячейки не принимаются. Вес расчётный, по геометрии и плотности стали.
Плотность новой марки обязательна; существующие плотности импорт не изменяет.
Поставщик необязателен, но указанное название должно однозначно соответствовать
активному поставщику. Новые материалы/характеристики требуют `materials/manage`,
новые марки — `materials/manage` или `nesting_catalog/manage`.

## Серверный контракт

- `GET /api/inventory/sheet-import/template` — книга с пустым листом ввода, инструкцией и текущим справочником.
- `POST /api/inventory/sheet-import/preview` — multipart `file`, `factoryId`; строки, ошибки, итоги, `previewHash`, предыдущий импорт. Без записей в БД.
- `POST /api/inventory/sheet-import/commit` — тот же файл и завод, `operationId`, `previewHash`, необязательный `previousImportId`. Ответ: `batchId`, `receiptCount`, `quantity`, `weightKg`, `replayed`.

Повтор сетевого запроса использует прежний `operationId`. Сбой после фиксации прихода
не приводит к повторному начислению. Новый приход тех же данных требует нового
`operationId` и идентификатора последнего показанного импорта. Конкурентное изменение
справочника или предыдущего импорта возвращает 409 и требует новой проверки.
Сравнение повторов учитывает завод, вид листа, марку, размеры, поставщика и суммарное
количество; порядок строк, имя файла и комментарии на него не влияют.

RPC работают с пользовательской сессией, проверяют `auth.uid()`, право управления
складом и завод. Создание каталога, пополнение и история атомарны. Для согласованности
импорты сериализованы транзакционной advisory-блокировкой; при фиксации короткая
блокировка справочников исключает их одновременное изменение ручными формами.
Журнал `inventory_sheet_imports` доступен только на чтение в пределах разрешённых
заводов (`inventory/view` или `inventory_history/view`). Прямые записи закрыты.
Новые политики добавлены отдельной миграцией; исторический снимок RLS cutover не меняется.

История склада содержит имя файла и номер строки в комментарии прихода, а также
`sheet_import_id` и `sheet_import_row` для точной связи с журналом. Импорт не создаёт
закупочные заявки, поставки по заказам, брони или деловые остатки.

## Проверка и выпуск

`npm run test:sheet-inventory-import` проверяет книгу и интерфейс. Для теста БД нужна
отдельная локальная БД с актуальной полной схемой:

```sh
FULL_SCHEMA_TEST_DATABASE_URL=postgresql://localhost/crm_sheet_import_test \
FULL_SCHEMA_REPLAY_ONLY=true node scripts/test-inventory-transfers-full-schema.mjs
SHEET_IMPORT_TEST_DATABASE_URL=postgresql://localhost/crm_sheet_import_test \
npm run test:sheet-inventory-import:db
```

Первая команда пересоздаёт только указанную локальную тестовую БД. Не использовать
существующую общую БД других задач. Тесты проверяют реальный откат второй строки,
вес, сохранение броней, доступ по заводам, повтор и конкурентные запросы.

Для выпуска нужна миграция `20260922183000_sheet_inventory_import.sql` перед
включением нового интерфейса. Внешние миграции, push и deploy выполняются только
после отдельного подтверждения оператора. Проверка production — чтение страницы
склада, скачивание шаблона и сверка SHA; реальный приход требует отдельного поручения.

## Результаты локальной проверки

- 14 тестов файла, HTTP-границ и предпросмотра прошли; TypeScript и ESLint всех изменённых файлов — без ошибок. Production-сборка Next.js прошла, все три API-маршрута включены.
- Полная схема воспроизведена в отдельной PostgreSQL БД: 18 Prisma и 345 Supabase миграций. Тест импорта проверил права и изоляцию заводов, 2 000 строк, вес, сохранение броней, откат и конкурентные запросы. Существующий тест складского жизненного цикла также прошёл.
- В локальном браузере проверены реальные компонент, ExcelJS-обработчик и PostgreSQL RPC. Проверены скачивание, заполнение, предпросмотр, приход, повреждённый ответ после фиксации с безопасным повтором, предупреждение о дубликате и осознанный новый приход. Только пользовательская сессия и Next.js refresh заменены тестовым окружением; production не использовался.
- Визуально проверены три листа шаблона и окно при ширине 1440 и 390 пикселей; таблица прокручивается отдельно от кнопок.
- Статические проверки матрицы RLS и порядка миграций прошли. Общий `test:rls-matrix-cutover:db` останавливается до сценариев импорта: старая фикстура `supabase/tests/rls_matrix_permissions_test.sql` записывает руководителя подразделения напрямую, что отклоняет существующий `private.organization_validate_department()` («Руководитель меняется через назначение сотрудника»).
- Общий ESLint (без временных артефактов `.runtime`) сообщает 34 ошибки и 31 предупреждение в файлах, не отличающихся от `origin/main`. Эти сторонние проблемы не исправлялись в рамках импорта.
